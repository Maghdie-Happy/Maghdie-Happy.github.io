# Connectly User Stories & Atomic Task Breakdown

## EPIC 1: User Registration, Authentication & POPIA Privacy
---------------------------------------------------------------------------------------------------------------------------------
**US-01:** POPIA-Compliant User Registration \
As a Belhar Job Seeker or Household Employer, \
I want to create an account with explicit POPIA consent tracking, \
So that my personal data is legally protected and securely processed under South African regulations. 

Acceptance Criteria:
- Password must be securely hashed using salted bcrypt prior to persistence.
- Registration must require explicit true/false checking for POPIA consent.
- System must record `popia_consent_at` timestamp in the database.

Atomic Technical Tasks: \
**[Task 1.1]** Design `users` table schema in MySQL 8.0 containing `popia_consent` and `popia_consent_at` fields. \
**[Task 1.2]** Build RESTful POST API endpoint `/api/auth/register` handling user payload validation. \
**[Task 1.3]** Implement bcrypt salted password hashing algorithm inside the Auth & Identity Service. \
**[Task 1.4]** Construct front-end user registration form interface in HTML5/JS with mandatory POPIA checkbox.

---------------------------------------------------------------------------------------------------------------------------------

## EPIC 2: Job Listing Management & Geo-Matching
---------------------------------------------------------------------------------------------------------------------------------
**US-02:** Household Gig Posting \
As a Household Employer in Belhar, \
I want to post a local job listing with a specific category, budget, and street address, \
So that nearby local workers can apply directly without middleman agency costs. 

Acceptance Criteria:
- Job posting must link directly to a valid `employer_id` and existing `category_id`.
- Budget can be configured as FIXED or HOURLY in South African Rand (ZAR).
- Address details must record latitude and longitude coordinates for local geo-matching.

Atomic Technical Tasks: \
**[Task 2.1]** Define `jobs` and `job_categories` relational tables with foreign key contraints in MySQL. \
**[Task 2.2]** Build Geo-Matching radius query logic to filter active listings within Belhar. \
**[Task 2.3]** Develop front-end job creation portal UI and connect to RESTful POST `/api/jobs` endpoint. \
**[Task 2.4]** Implement client-side caching mechanism for static job category drop-down listings.

---------------------------------------------------------------------------------------------------------------------------------

## EPIC 3: Job Application & Direct Candidate Matching
---------------------------------------------------------------------------------------------------------------------------------
**US-03:** One-Click Gig Application \
As a Belhar Job Seeker operating a resource-constrained Android smartphone, \
I want view available local jobs and submit an application with minimal data usage, \
So that I can secure employment quickly without consuming expensive cellular data packages. 

Acceptance Criteria:
- Mobile interface must render lightweight JSON payloads.
- Prevent duplicate job applications using database unique constraints (`uq_job_seeker`).
- Application state must transition cleanly from PENDING to ACCEPTED or REJECTED.

Atomic Technical Tasks: \
**[Task 3.1]** Design `job_applications` table with composite unique key constraints (`job_id, seeker_id`). \
**[Task 3.2]** Build POST endpoint `/api/applications/apply` handling instant application submission. \
